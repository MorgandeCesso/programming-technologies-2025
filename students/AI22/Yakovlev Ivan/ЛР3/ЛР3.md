# Лабораторная работа №3. Отчёт.

**Цель работы:** освоить применение векторных баз данных и методов семантического поиска для работы с текстовыми данными, а также получить навыки интеграции этих компонентов с последующим использованием в задачах машинного обучения и NLP.

## План выполнения
- Развёртывание изолированной среды разработки (devcontainer);
- Изучение структуры проекта и подготовка модулей для взаимодействия с Milvus;
- Реализация парсинга текстов и разбиения на фрагменты (чанки);
- Выполнение двух практических заданий.

## 1. Подготовка окружения и первичный запуск

Для обеспечения воспроизводимости и единообразия среды была использована технология devcontainer. Она позволяет упаковать все необходимые зависимости (Python, Milvus, Attu) в Docker-контейнеры, исключая проблемы с версиями библиотек и конфликтами на хосте. После клонирования репозитория с лабораторной работой мы открыли папку проекта в Visual Studio Code и выполнили команду «Reopen in Container». В результате автоматически были запущены пять cервисов:
- `app` – среда для выполнения Python-кода;
- `standalone` – сервер Milvus;
- `etcd` – координационная служба для Milvus;
- `minio` – объектное хранилище для данных Milvus;
- `attu` – веб-интерфейс для администрирования Milvus (доступен на порту 8000).

Чтобы убедиться в корректной работе всех компонентов, мы выполнили тестовый запуск скрипта `example_usage.py`, который демонстрирует полный цикл: подключение к Milvus, создание коллекции, загрузку документов и семантический поиск. Скрипт отработал без ошибок, но использовал центральный процессор (CPU) для генерации эмбеддингов. Для ускорения дальнейших экспериментов было решено задействовать графический процессор (GPU).

## 2. Задание №1. Активация GPU

Модель `intfloat/multilingual-e5-base`, применяемая для получения векторных представлений текста, может работать на GPU, что существенно ускоряет вычисления. В файле `docker-compose.yml` в описании сервиса `app` присутствовала закомментированная строка `# gpus: all`. Мы раскомментировали её, добавив тем самым проброс видеокарты в контейнер. После этого контейнеры были пересобраны и перезапущены командой `docker-compose up -d --build`.

Внутри контейнера мы проверили доступность GPU с помощью Python:
```python
import torch
print(torch.cuda.is_available())  # вернуло True
```
При повторном запуске `example_usage.py` в логах появилась строка `Устройство: cuda`, подтверждающая использование видеокарты. Это позволило сократить время генерации эмбеддингов и убедиться, что код корректно определяет доступное оборудование (благодаря встроенной логике в файле `embedder.py`).

## 3. Задание №2. Разработка REST API на базе Django Rest Framework

Второй этап работы заключался в создании веб-сервиса, предоставляющего удобный интерфейс для взаимодействия с Milvus. Мы использовали Django Rest Framework (DRF) – популярный инструмент для быстрого построения API.

### 3.1. Создание проекта и структуры

Внутри контейнера, находясь в директории `/workspaces`, мы выполнили:
```bash
django-admin startproject milvus_api
cd milvus_api
python manage.py startapp search
```
Затем в папку `search/` были скопированы ранее написанные модули: `milvus_client.py`, `embedder.py`, `text_parser.py`, `document_processor.py`. Это позволило переиспользовать готовую логику работы с векторной БД и эмбеддингами.

### 3.2. Настройка и исправление импортов

При первом запуске сервера возникла ошибка импорта: в файлах модулей использовались абсолютные ссылки (`from milvus_client import ...`), тогда как после перемещения в пакет `search` они должны быть относительными. Мы заменили все подобные импорты на `from .milvus_client import ...` и убедились в наличии файла `__init__.py` в папке приложения. После этого сервер запустился успешно.

### 3.3. Реализация эндпоинтов

В файле `services.py` были созданы глобальные экземпляры клиента Milvus и эмбеддера, чтобы не пересоздавать их при каждом запросе. Далее мы написали сериализаторы для валидации входных данных и вьюхи, обрабатывающие следующие операции:

- `GET /api/collections/` – получение списка всех коллекций;
- `POST /api/collections/` – создание новой коллекции (требуется JSON с полями `name`, `dimension`, `metric_type`);
- `POST /api/upload/` – загрузка текстового файла, его чанкирование, генерация эмбеддингов и сохранение в указанную коллекцию;
- `GET /api/search/` – семантический поиск по коллекции (параметры: `q` – текст запроса, `collection_name`, `top_k`);
- `DELETE /api/collections/<name>/` – удаление коллекции.
```python
@api_view(['POST'])
def upload_file(request):
    """
    Загрузка файла, чанкирование, генерация эмбеддингов и сохранение в Milvus.
    """
    serializer = FileUploadSerializer(data=request.data)
    if not serializer.is_valid():
        return Response(serializer.errors, status=status.HTTP_400_BAD_REQUEST)

    uploaded_file = serializer.validated_data['file']
    collection_name = serializer.validated_data['collection_name']

    # Сохраняем файл во временную директорию
    with tempfile.NamedTemporaryFile(delete=False, suffix='.txt') as tmp:
        for chunk in uploaded_file.chunks():
            tmp.write(chunk)
        tmp_path = tmp.name

    try:
        processor = DocumentProcessor(
            milvus_client=milvus_client,
            chunk_size=256,
            chunk_overlap=64,
            embedding_function=embedding_function
        )
        result = processor.process_file(tmp_path, collection_name)
    except Exception as e:
        result = {'success': False, 'error': str(e)}
    finally:
        os.unlink(tmp_path)  

    if result['success']:
        return Response({
            'message': f"Файл обработан, загружено {result['chunks_count']} чанков",
            'chunks_count': result['chunks_count'],
            'inserted_ids': result.get('inserted_ids', [])
        }, status=status.HTTP_201_CREATED)
    else:
        return Response({'error': result.get('error', 'Неизвестная ошибка')},
                        status=status.HTTP_400_BAD_REQUEST)


@api_view(['GET'])
def search(request):
    """
    Семантический поиск по коллекции.
    """
    serializer = SearchQuerySerializer(data=request.query_params)
    if not serializer.is_valid():
        return Response(serializer.errors, status=status.HTTP_400_BAD_REQUEST)

    q = serializer.validated_data['q']
    collection_name = serializer.validated_data['collection_name']
    top_k = serializer.validated_data['top_k']

    # Генерируем эмбеддинг запроса
    query_vector = embedder.encode_query(q)

    try:
        results = milvus_client.search(
            collection_name=collection_name,
            query_vectors=[query_vector],
            top_k=top_k
        )
        # results[0] – список результатов для одного запроса
        hits = results[0] if results else []
        serializer = SearchResultSerializer(hits, many=True)
        return Response(serializer.data)
    except Exception as e:
        return Response({'error': str(e)}, status=status.HTTP_400_BAD_REQUEST)

@api_view(['GET', 'POST'])
def collections(request):
    if request.method == 'GET':
        try:
            collections = utility.list_collections()
            return Response({'collections': collections})
        except Exception as e:
            return Response({'error': str(e)}, status=status.HTTP_500_INTERNAL_SERVER_ERROR)
    
    elif request.method == 'POST':
        serializer = CollectionCreateSerializer(data=request.data)
        if not serializer.is_valid():
            return Response(serializer.errors, status=status.HTTP_400_BAD_REQUEST)
        
        name = serializer.validated_data['name']
        dimension = serializer.validated_data['dimension']
        metric_type = serializer.validated_data['metric_type']
        
        try:
            milvus_client.create_collection(
                collection_name=name,
                dimension=dimension,
                metric_type=metric_type,
                description=f"Коллекция {name}"
            )
            return Response({'message': f'Коллекция {name} создана'}, status=status.HTTP_201_CREATED)
        except Exception as e:
            return Response({'error': str(e)}, status=status.HTTP_400_BAD_REQUEST)
@api_view(['DELETE'])
def delete_collection(request, name):
    """
    Удаление коллекции.
    """
    try:
        milvus_client.delete_collection(name)
        return Response({'message': f'Коллекция {name} удалена'})
    except Exception as e:
        return Response({'error': str(e)}, status=status.HTTP_400_BAD_REQUEST)

```
В процессе отладки мы столкнулись с ошибкой сериализации объекта `RepeatedScalarContainer`, возвращаемого методом `insert_data` клиента Milvus. Проблема была решена преобразованием результата в обычный список Python с помощью `list(insert_result.primary_keys)`. Также потребовалось корректно обрабатывать русскоязычные запросы в GET-параметрах – для этого в curl использовалась опция `--data-urlencode`.

### 3.4. Тестирование API

Для проверки работоспособности мы выполнили серию запросов через терминал.

- Создание коллекции:

  Ответ: `{"message":"Коллекция test_api создана"}`

- Загрузка файла:

  Ответ содержал количество обработанных чанков и их идентификаторы.

- Поиск:
  ```bash
  curl -G "http://localhost:8001/api/search/" --data-urlencode "q=машинное обучение" --data-urlencode "collection_name=test_api" --data-urlencode "top_k=3"
  ```

  В ответе получен JSON с тремя записями, имеющими высокую степень схожести (distance около 0.84).

- Список коллекций:
  ```bash
  curl http://localhost:8001/api/collections/
  ```
  Вернул `{"collections":["documents","test_api"]}`.

- Удаление коллекции:
